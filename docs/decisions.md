# Decision Log

> One or two lines per decision. Newest at the bottom. Format:
> `[Phase XX] Decision: … | Reason: … | Alternatives considered: …`
> `[Pre-00]` entries were made by the user before the repository existed; they bind every phase like any other decision.

[Pre-00] Decision: The web app lives in its own repository, `EcomDemo-Web`, with its own phases from Phase 0, following `docs/backend/integration-guide.md` (sections 10-13) | Reason: separate history, CI, images and releases; the two teams share only the API contract | Alternatives considered: a folder in the backend repository
[Pre-00] Decision: Same rules and lifecycle as the backend: one technology per phase; `feature/`, `fix/ki-`, `chore/` branches; one open PR; merge commits only; merge verification; `phase-XX-complete` and `ki-XXX-fixed` tags; never delete branches; a known-issues register | Reason: the user's workflow, proven over the backend's phases | Alternatives considered: none
[Pre-00] Decision: React + TypeScript (strict) on Vite, React Router, TanStack Query, openapi-typescript + openapi-fetch, React Hook Form + Zod, Vitest + Testing Library + MSW, Playwright | Reason: the guide's stack assumption; every later tool supports it | Alternatives considered: Next.js, Angular, Vue (the guide keeps the phase order if the framework changes)
[Pre-00] Decision: Phase 9 (Design System) ports the EcomDemo design system in `design-system/` with plain CSS on its tokens, instead of the guide's proposed Tailwind CSS + Radix primitives | Reason: the user asked for a site that does not look AI-built; untouched Tailwind/shadcn/Radix defaults, rounded icon sets and gradients are the most common fingerprint of generated sites (`design-system/README.md`, "Not a generated site"); the guide calls its roadmap a proposal the team edits | Alternatives considered: Tailwind with custom tokens (pulls towards the same defaults); Radix for dialogs and menus (native `<dialog>` and small own components cover the storefront's needs)
[Pre-00] Decision: The browser only ever talks to its own origin; `/api` is proxied to the gateway (Vite in dev and preview, nginx in the image, one ingress host in Kubernetes) | Reason: the pinned backend's CORS preflights fail (backend KI-041) and same-origin needs no CORS at all | Alternatives considered: calling `http://localhost:8080` cross-origin (breaks on every preflight until the pin moves past KI-041)
[Pre-00] Decision: The UI shows prices in Indian rupees (₹, `en-IN` grouping) | Reason: the backend models no currency (web KI-009); the owner is based in India and the design system is built for rupees | Alternatives considered: a currency-less number (unclear to shoppers)
[Pre-00] Decision: The backend is pinned at `ki-001-fixed` | Reason: the tag the integration guide was written against; the OpenAPI documents work through the gateway from this tag on | Alternatives considered: tracking backend `main` (moves under the web app's feet)
[Pre-00] Decision: Human content (staff notes, About, policy wording, photos, names) is written by the user; code leaves `TODO(owner)` placeholders | Reason: invented human content is what makes a site feel generated, and signing words someone did not write is dishonest | Alternatives considered: generated placeholder prose
